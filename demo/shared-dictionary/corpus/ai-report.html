Summary

The migration from the legacy PostgreSQL 11 cluster to the new managed instance is mostly complete. Eight tables remain, all of them in the billing schema, and they are blocked on a foreign key constraint that the old application still relies on. We recommend scheduling a short maintenance window next week so that the remaining tables can be moved together, rather than one at a time.

Overall performance has improved. Query latency dropped by about twelve percent, mostly because the new instance has more memory and the connection pool is configured correctly. However, a small number of reports are now slower, and we believe this is caused by missing indexes that were created manually on the old cluster and were never added to the migration scripts.

Next steps

  1. Add the three missing indexes to the migration scripts and apply them to the new instance.
  2. Schedule a maintenance window for the billing schema and notify the support team in advance.
  3. Remove the legacy foreign key once the application no longer depends on it.
  4. Decommission the old cluster after two weeks without incidents.
